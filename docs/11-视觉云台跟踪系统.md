# 视觉云台跟踪系统

当前桌面程序已经拆分为 PySide6 UI、视觉流水线、控制状态机和硬件传输层。闭环为：

```text
摄像头 → YOLO人体检测 → ByteTrack ID → 逐ID Kalman
→ 用户在UI中选择目标 → 近距离瞄准策略 → 像素偏差转角度
→ 双轴PI速度请求 ─┐
                  ├→ 控制仲裁 → 统一限速/限加速度/软限位
停止状态下WASD ────┘→ 共享二进制串口 ─→ ESP32 `(pan,tilt)` → 云台
                                       └→ ESP32 8 kHz 调制 → 超声阵列
麦克风 → DSP → 8 kHz PCM_U8 → 音频分包 ─┘
             └→ 后台增量 STFT → UI 实时发送频谱（dBFS）
```

视觉层只报告人物轨迹；自动追踪和 WASD 都不能直接访问串口。`ControlService` 是唯一云台命令出口，因此两种控制模式不会同时生效。

## 运行

桌面 UI 需要 Python 3.10～3.12；当前开发机建议直接使用 Python 3.11。先同步依赖：

```powershell
uv sync --python 3.11
```

只观察算法、不连接云台：

```powershell
$env:PYTHONPATH = ".\src"
uv run python -m vision_gimbal.main
```

连接ESP32，例如串口为`COM5`：

```powershell
$env:PYTHONPATH = ".\src"
uv run python -m vision_gimbal.main --serial-port COM5
```

波特率默认 460800，与 `src/full_size/full_size.ino` 一致。云台和实时音频由同一个 `SerialDeviceLink` 通过二进制协议复用；程序按 10 Hz 控制节拍发布目标角度，串口断开时后台自动重连，不阻塞 YOLO。主要运行参数位于 `configs/vision_gimbal.toml`，命令行的串口、波特率、摄像头索引和推理设备参数可以覆盖配置文件。

当前配置默认启用音频控制面板，但不会自动打开麦克风。仍可在不配置串口时运行视觉仿真；此时麦克风链路的开始按钮保持禁用。

## UI 操作

- 程序启动后默认处于“停止追踪 / 手动控制”状态，但摄像头和人物识别继续运行。
- 单击画面中的人物框将其选中；蓝框表示已选中但尚未生效的目标。
- 单击“开始追踪”后才进入自动闭环；黄色框表示当前实际追踪目标。
- 自动追踪中点击另一个人只会形成待切换目标，再单击“切换目标”才会生效，避免误点导致云台突然转向。
- 单击“停止追踪”会退出视觉闭环并保持最后指令角度，不会关闭摄像头或切断舵机电源。
- 停止状态下可按住 `W/A/S/D` 控制上、左、下、右；自动追踪中这些按键会被忽略。
- 窗口失去焦点时会自动释放全部方向键，避免按键卡住后持续转动。
- 黄色框表示当前活动目标，红色十字表示阵列瞄准中心。
- 紫色斜十字表示实际送入PI的瞄准点；近距离模式触发后它会移至人体框约30%高度。
- 虚线人物框表示 Kalman 短期预测，目标丢失超时后系统停止追踪，不会自动换到其他人物。

### 麦克风与超声阵列

- 串口连接后，单击“开始麦克风链路”才会打开系统输入设备并依次建立 `STREAM_START`、PCM 音频传输和 ESP32 超声调制输出。
- 单击“关闭麦克风链路”会先停止采集，再请求 ESP32 静音并停止流，最后释放麦克风；视觉识别和云台控制继续运行。
- `RAW / LOUD`、`STANDARD / BOOST`、`DSB-AM / SRAM` 均可在右侧面板即时切换。若音频正在传输，程序会自动停止并用新参数重新建立音频流，不会重启摄像头、YOLO 或舵机控制。
- 面板显示 ESP32 播放状态、缓冲样本数、欠载和主机丢包。连续出现欠载或丢包时，先处理串口吞吐和系统调度问题，不要继续增加增益。
- 画面下方的实时频谱取自电脑端限幅后、PCM_U8 量化前的 8 kHz 发送音频，以固定 dBFS 色标显示最近数秒的时频变化。它不是 40 kHz 超声载波测量，也不是经过声压标定的 dB SPL。
- 频谱 FFT 在独立有界线程中运行；分析来不及时只丢弃旧的可视化音频块，不阻塞串口音频、视觉识别或云台控制。关闭麦克风链路后频谱会清空并回到等待状态。
- `LOUD` 是 ESP32 端响度映射，`BOOST` 会提高包络峰值；两者叠加更容易增加失真和功放压力。初次上电建议从 `RAW + STANDARD + DSB-AM` 开始，再逐项比较。

默认模式也可在 `configs/vision_gimbal.toml` 的 `[audio.stream]` 中设置：

```toml
processing = "raw"       # raw 或 loud
boost = false             # false=STANDARD，true=BOOST
modulation = "dsb_am"    # dsb_am 或 sram
```

实时频谱参数位于 `[audio.spectrum]`：

```toml
enabled = true
window_ms = 40.0
hop_ms = 20.0
history_s = 6.0
refresh_hz = 10.0
min_dbfs = -80.0
max_dbfs = 0.0
queue_blocks = 4
```

当前发送采样率为 8 kHz，因此频谱纵轴固定为 0～4 kHz；默认语音低通为 3 kHz。`queue_blocks` 只限制频谱分析队列，不改变麦克风采集队列或串口发送队列。

## 标定

- 当前装机配置已将视觉水平轴反向；垂直轴方向保持不变。
- 首次装机必须校准水平/垂直视场角、瞄准点偏移、两轴方向和机械限位。
- PI默认参数偏保守；先只调`Kp`，稳定后再小幅增加`Ki`。舵机堵转或供电不足不能通过PID解决。
- 不配置`--serial-port`时仍会完整运行控制计算，但不会驱动硬件。

配置中的 `last_commanded_pose` 和 UI 中的“指令角度”不是舵机编码器反馈。当前硬件没有角度回读，程序只能显示最后下发的目标角度。

正式实现位于 `src/vision_gimbal`：

- `domain`：不可变数据合同与状态枚举；
- `vision`：YOLO、ByteTrack、重复框过滤和逐 ID Kalman；
- `control`：显式目标锁定、近距离策略、PI、WASD、仲裁和运动限制；
- `application`：视觉服务、会话状态机和唯一命令出口；
- `infrastructure`：OpenCV 摄像头、串口和空云台适配器；
- `ui`：PySide6 窗口、坐标映射、绘制和线程适配。

旧 `src/cv_test_deprecated` 算法文件暂时保留用于回归参考。实时麦克风可从同一桌面 UI 手动启停，也可使用 `utils/mic_stream_cli.py` 独立测试。

## 近距离上半身瞄准

当锁定人体的框高达到画面高度90%、且接触画面上/下边缘并持续5个真实检测帧时，系统切换到近距离模式。它保留水平瞄准点，仅将垂直瞄准点从框中心改到框高约30%处，使现有垂直PI向上重构图。框高低于70%、上下边缘都完整可见并持续10帧后才退出，避免在阈值附近反复切换。

这些参数位于 `configs/vision_gimbal.toml` 的 `[close_range]`。Kalman 预测帧不会触发近距离状态切换；停止、切换目标或目标丢失超时都会清空近距离状态。

## 安全边界

“停止追踪”表示停止视觉自动控制并让云台保持最后角度，不是硬件急停，也不会释放舵机扭矩。需要物理急停或断电保护时，必须扩展 ESP32 协议和硬件电源控制。

## 低频深度与相对声场分析

`[spatial_field]` 是默认关闭的附加显示功能。它每隔一段时间只提交一张最新相机帧给后台线程，队列容量固定为一；分析来不及完成时会丢弃旧帧，绝不积压或阻塞 YOLO、10 Hz 云台控制、串口和实时音频。

该功能不会产生任何云台、音频或 ESP32 指令。深度图只在后台用于计算，UI 不单独展示它；主视频保持原有跟踪与交互，独立的“相对声场叠加画面”显示同一摄像头画面及其半透明热图。声场图中不显示来源帧、推理耗时或其他角标。它是可见表面的**直达、相对自由场**估计，不是 dB SPL 测量，未包含房间反射、遮挡后的场、空气非线性或阵面实测修正。

相机内参由 `[camera.calibration]` 给出，配置中的 `fx=fy=1450`、`cx=960`、`cy=540` 对应 1920×1080。程序会按当前相机分辨率缩放这些值；在当前 1280×720 配置下等效为 `fx=fy=966.67`、`cx=640`、`cy=360`。畸变系数顺序与 OpenCV 一致：`k1, k2, p1, p2, k3`。

首次启用前，需要准备 320×192 的 OpenVINO 深度模型。安装可选运行时并从模型目录导出：

```powershell
uv sync --extra spatial
New-Item -ItemType Directory -Force models
Push-Location models
uv run --extra spatial python -c "from ultralytics import YOLO; YOLO('yolo26n-depth.pt').export(format='openvino', imgsz=(192, 320))"
Pop-Location
```

### 深度时序稳定

声场面板只显示深度推理所用的来源帧及其热图，不再把旧热图叠加到最新视频帧，因此云台或相机运动不会造成错帧跳变。后台会在低分辨率深度图上执行保守的对数域时序稳定：仅当两帧大面积重叠且残差一致时，才做受限的全局尺度校正；校正后仍相近的像素才指数平滑，局部大变化、无效值、分辨率变化和超过 `max_gap_s` 的断帧直接采用新值或重置状态。

参数位于 `[spatial_field.depth.temporal]`。`interval_s` 默认设为 0.5 s；应根据实际 P95 推理耗时调大，避免后台长期满载。该稳定器不估计相机运动，因此它改善的是静态或缓慢变化视角下的单目尺度闪烁；若需要在快速云台运动中保持地图连续，应在后续版本接入云台姿态重投影或光流对齐。

导出目录应为 `models/yolo26n-depth_openvino_model`，与默认配置一致。确认 Intel Arc 图形驱动可被 OpenVINO 检出后，将 `spatial_field.enabled` 改为 `true`。若 320×192 仍超出性能预算，使用 256×160 重新导出模型并同步修改 `input_width`、`input_height`；静态 OpenVINO 模型不能安全地在运行中变更输入大小。
