# 实时音源与音频流协议

> 版本：v1.3
> 日期：2026-09-13
> 电脑端：`src/vision_gimbal` 与 `utils/mic_stream_cli.py`  
> 固件端：`src/full_size`  
> 默认物理链路：460800 baud、8N1 串口

## 1. 数据流

```text
电脑麦克风 ──────┐
立体声混音 ──────┤→ 48 kHz float32 / 10 ms
WASAPI进程回环 ──┘   不受物理扬声器音量/静音影响
→ 单声道
→ 250 Hz高通
→ 3 kHz抗混叠低通
→ 有状态重采样到8 kHz
→ 慢速电平控制、压缩和限幅
→ 可选PCM16 WAV监听录音抽头
→ PCM_U8，静音值128
→ 160样本/20 ms
→ COBS + CRC16二进制帧
→ 唯一SerialDeviceLink
→ ESP32协议服务器
→ 2048样本内部RAM环形缓冲
→ 480样本预缓冲
→ 8 kHz GPTimer
→ UI选择的 RAW/LOUD + DSB-AM/SRAM + STANDARD/BOOST
→ LEDC 40 kHz可变占空比
→ GPIO4、SN74HC125、TC4428A和120阵元
```

电脑只传可听基带PCM。40 kHz载波、调制查表、占空比映射和故障静音保留在ESP32。

## 2. 电脑端配置

音频控制面板默认启用，但采集和传输不会自动开始。配置 `configs/vision_gimbal.toml`：

```toml
[serial]
port = "COM5"
baudrate = 460800

[audio]
enabled = true
auto_start = false

[audio.capture]
source = "system_loopback"
device = ""
channels = 1
stereo_mix_device = "立体声混音"
stereo_mix_channels = 2
process_loopback_helper = ""
sample_rate = 48000

[audio.activity_gate]
enabled = true
system_loopback_only = true
silence_threshold_dbfs = -60.0
resume_threshold_dbfs = -50.0
release_ms = 1000

[audio.stream]
processing = "loud"
boost = true
modulation = "dsb_am"

[audio.recording]
enabled = false
path = "../output/audio_recordings/post_limiter_{timestamp}.wav"
```

录音抽头位于压缩和-1.5 dBFS限幅之后、PCM_U8量化之前，输出为单声道8 kHz、16-bit PCM WAV。`{timestamp}`会替换为启动录音的本地时间；相对路径以配置文件目录为基准。录音只在音频流处于发送状态时写入，停止流或退出程序会正常封口WAV。

桌面程序启动后，`ApplicationRuntime`先打开共享设备链路，再启动视觉、云台控制和音频服务。默认音源为“电脑声音（静音无关回环）”；它使用 Windows 进程回环捕获除本程序及子进程外的系统音频。物理扬声器可以静音，捕获音量和阵列输出不会随之降低。

传输中改变音源会自动静音、清空旧数据并重启流。进程回环连续静音 1 s 后会停止 ESP32 音频流和 PWM；检测到新内容后重新预缓冲并恢复。这与物理扬声器的静音状态无关。

若只测试麦克风链路：

```powershell
uv run python .\utils\mic_stream_cli.py --serial-port COM5
```

只测试立体声混音链路：

```powershell
uv run python .\utils\mic_stream_cli.py --serial-port COM5 --source stereo_mix
```

测试不受物理扬声器静音影响的进程回环：

```powershell
uv run python .\utils\mic_stream_cli.py --serial-port COM5 --source system_loopback
```

首次使用会调用 `utils/build_wasapi_process_loopback.ps1` 自动编译原生辅助程序，需要 `g++` 在 `PATH` 中。也可先手动执行：

```powershell
.\utils\build_wasapi_process_loopback.ps1
```

`stereo_mix_device`使用设备名查询而不是数字索引，避免声卡插拔后索引变化。可用 `uv run python -m sounddevice` 查看实际名称。当前 Realtek 驱动下默认名称为“立体声混音”。

也可以只对本次命令启用录音并覆盖配置路径：

```powershell
uv run python .\utils\mic_stream_cli.py --serial-port COM5 --record-output .\output\processed.wav
```

按 `Ctrl+C` 时，工具先发送静音和停止流，再关闭串口。程序静音不能代替12 V物理断电。

## 3. 预处理参数

| 阶段 | 当前配置 | 说明 |
|---|---:|---|
| 采集 | 48 kHz、float32、10 ms | 进程回环固定48 kHz；PortAudio音源可配置44.1 kHz |
| 声道 | 平均为单声道 | 可在后续增加左/右声道选择 |
| 高通 | 250 Hz、二阶Butterworth | 去直流、震动和不可用低频 |
| 实测EQ | 关闭 | 不自动使用理论逆f²补偿 |
| 低通 | 3 kHz通带、4 kHz阻带 | Kaiser窗FIR，重采样前抗混叠 |
| 重采样 | 8 kHz | 保存滤波和分数相位状态 |
| 电平 | -8 dBFS目标、最大+30 dB | 高响度配置；静音时冻结增益 |
| 压缩 | -12 dBFS、3:1 | 10 ms attack、120 ms release |
| 限幅 | -1.5 dBFS | 量化前最终保护 |
| 量化 | unsigned 8-bit | `round(128+128*x)`并限幅 |

电脑根据ESP32上报的缓冲水位，以不超过±500 ppm的微量比率修正补偿两端音频时钟漂移。

## 4. 线上帧

原始帧使用小端字段：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 2 | ASCII `UA` |
| 2 | 1 | 协议版本，固定1 |
| 3 | 1 | 消息类型 |
| 4 | 2 | flags |
| 6 | 2 | payload长度，最大512 |
| 8 | 4 | session ID |
| 12 | 4 | sequence |
| 16 | 4 | audio sample index |
| 20 | N | payload |
| 20+N | 2 | CRC-16/CCITT-FALSE |

CRC参数为 `poly=0x1021`、`init=0xFFFF`、`xorout=0`。线上编码为：

```text
0x00 + COBS(header + payload + crc16) + 0x00
```

前导零用于从ESP32启动日志或旧文本协议中重新建立边界；连续零为空帧，直接忽略。

### 4.1 flags

| bit | 名称 |
|---:|---|
| 0 | ACK_REQUIRED |
| 1 | IS_ACK |
| 2 | ERROR |
| 3 | END_OF_STREAM |

### 4.2 消息类型

| 值 | 方向 | 名称 |
|---:|---|---|
| `0x01` | PC→ESP | HELLO |
| `0x02` | PC→ESP | STREAM_START |
| `0x03` | PC→ESP | AUDIO_DATA |
| `0x04` | PC→ESP | STREAM_STOP |
| `0x05` | PC→ESP | SET_MUTE |
| `0x06` | PC→ESP | GIMBAL_SETPOINT |
| `0x07` | PC→ESP | PING |
| `0x81` | ESP→PC | HELLO_ACK |
| `0x82` | ESP→PC | COMMAND_ACK |
| `0x83` | ESP→PC | STATUS |
| `0x84` | ESP→PC | LOG |
| `0x85` | ESP→PC | ERROR |
| `0x87` | ESP→PC | PONG |

## 5. STREAM_START

16字节payload：

| 偏移 | 类型 | 字段 | V1值 |
|---:|---|---|---:|
| 0 | u32 | sample rate | 8000 |
| 4 | u16 | packet samples | 160 |
| 6 | u16 | prebuffer samples | 480 |
| 8 | u8 | sample format | 1=PCM_U8 |
| 9 | u8 | channels | 1 |
| 10 | u8 | modulation | 0=DSB、1=SRAM |
| 11 | u8 | processing | 0=RAW、1=LOUD |
| 12 | u8 | drive | 0=STANDARD、1=BOOST |
| 13 | u8 | underflow policy | 1 |
| 14 | u16 | data timeout ms | 100 |

桌面UI可请求 `RAW/LOUD + DSB-AM/SRAM + STANDARD/BOOST` 的任意组合；当前整机配置默认为 `LOUD + DSB-AM + BOOST`。运行中切换会先停止旧流，再使用新参数发送 `STREAM_START`。只有收到与当前启动请求版本匹配的成功 `COMMAND_ACK` 后，链路才发送已排队的AUDIO_DATA。

电脑端同一时刻只等待一条可靠控制命令的ACK，避免固件单条ACK缓存被后续命令覆盖而使重试重复执行。音频帧保持不要求ACK。

## 6. 音频和状态

`AUDIO_DATA` payload是连续PCM_U8，正常为160字节。`sample_index`是payload首样本的绝对序号。音频帧不要求ACK，也不重传；损坏或过期音频直接丢弃。

ESP32每100 ms发送32字节STATUS，包含：

- `IDLE/PREFILL/PLAYING/DRAINING/MUTED/FAULT`；
- 静音状态；
- 缓冲样本数和容量；
- underrun、overrun、CRC错误和音频序号缺口；
- GPTimer过期样本跳过数；
- 最近音频帧距今毫秒数。

ESP32在PREFILL状态等待至少480样本。播放中若缓冲耗尽，立即停止PWM并回到PREFILL；超过100 ms没有收到有效音频则停止流并保持静音，必须重新STREAM_START。

## 7. 云台复用

`GIMBAL_SETPOINT` payload为两个小端有符号int16：

```text
pan_centidegrees, tilt_centidegrees
```

范围均为 `-9000..9000`。电脑端串口只有一个所有者；音频服务和控制服务都向 `SerialDeviceLink` 发布消息，不能各自打开同一个COM口。

## 9. 验收顺序

1. 不接12 V，仅验证HELLO、ACK、STATUS和云台帧；
2. 电脑发送数字生成的1 kHz、低幅PCM，检查缓冲无欠载；
3. 示波器确认GPIO4载波、占空比变化和停止行为；
4. 单驱动、单换能器逐级验证；
5. 分别启用麦克风、立体声混音和进程回环；
6. 将 Windows 物理扬声器静音，确认进程回环频谱与阵列音频仍正常；
7. 连续运行30分钟，要求CRC、overrun、underrun和timer skip均为0；
8. 最后根据实测声压确认 LOUD + BOOST 是可连续使用的最大允许档。

若出现“内置音频清楚、实时流不清楚”，先按 [13-实时音频传输排查.md](13-实时音频传输排查.md) 使用同字节、同模式文件流对照，并保存完整状态日志。
