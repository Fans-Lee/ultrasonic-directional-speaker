# 当前项目完整数据流

> 版本：v1.0  
> 日期：2026-09-01  
> 适用范围：`src/esp32_s3_4x3_min_test` 固件与当前 120 阵元单 GPIO 整机  
> 目标：让具备 Arduino、ESP32 或嵌入式基础的开发者在 10 分钟内理解当前系统

## 1. 先明确当前版本

当前软件和硬件来自两个迭代阶段：

- 固件仍按旧 4×3 原型配置 4 个 LEDC 通道：`GPIO4、GPIO5、GPIO6、GPIO7`；
- 当前 120 阵元整机只接入 `GPIO4`，再由缓冲器扇出为 12 路同相信号；
- `GPIO5～GPIO7` 仍可能被固件驱动，但没有进入当前 120 阵元发射板；
- 当前没有电子相位转向或逐阵元控制，波束方向由二维机械云台改变。

因此，理解当前行为时按以下优先级判断：

1. 实际固件行为以 `src/esp32_s3_4x3_min_test` 源码为准；
2. 当前整机接线以 [09-当前120阵元单GPIO接线.md](09-当前120阵元单GPIO接线.md) 为准；
3. [08-当前12阵元原型.md](08-当前12阵元原型.md) 和固件目录 README 用于解释历史 4×3 台架；
4. 01～07 文档中的 8/16 通道、视觉闭环和聚焦内容属于目标架构，不代表当前已经实现。

## 2. 总数据流

```text
离线 PCM WAV
    │  wav_to_audio_header.py
    ▼
audio_data.h：8 kHz、8-bit、单声道 PCM，存入 Flash
    │
    │                    串口命令
    │                       │
    │                       ▼
    │              controlTask → 命令队列
    │                               │
    │          GPTimer ISR ─────────┤ 通知
    │          8 kHz节拍            ▼
    └──────────────────────→ playbackTask
                                    │
                                    ▼
                         ModulationEngine
                     固定载波 / 纯音 / PCM音频
                                    │
                                    ▼
                            duty + sampleRate
                                    │
                                    ▼
                   LEDC Timer 0：默认40 kHz、10-bit
                                    │
                    GPIO4（GPIO5～7当前未接阵列）
                                    │
                                    ▼
                       SN74HC125：1路扇出12路
                                    │
                                    ▼
                          12片 TC4428A
                         12 V互补差分输出
                                    │
                                    ▼
                      12组×10只并联换能器
                                    │
                                    ▼
                          120阵元同相超声波束
                                    │
                                    ▼
                         空气非线性产生可听声
```

串口只传控制命令，不传实时音频。摄像头、PC 视觉和云台控制是独立链路，不进入当前 ESP32 音频调制代码。

## 3. 音频进入固件之前

转换工具位于 `utils/wav_to_audio_header.py`，处理过程为：

```text
未压缩PCM WAV
→ 多声道平均为单声道
→ 线性重采样到8 kHz
→ 去直流
→ 峰值归一化到约90%
→ 首尾各10 ms淡入淡出
→ 8位无符号PCM
→ 生成src/data/audio_data.h
```

生成的数组使用 `PROGMEM`，随固件烧入 Flash。当前头文件配置为：

| 项目 | 当前值 |
|---|---:|
| 采样率 | 8000 Hz |
| 样本格式 | 8-bit unsigned PCM |
| 样本数 | 176000 |
| 时长 | 22 s |
| `kAudioIsDemo` | `false` |

播放时每个采样节拍通过 `pgm_read_byte()` 直接读取一个字节，没有串口音频流、环形音频缓冲或音频 DMA。更换音频需要重新生成头文件并烧录。

## 4. 上电与软件任务

Arduino 入口 `esp32_s3_4x3_min_test.ino` 依次执行：

1. 启动 115200 波特率串口；
2. 初始化 `UltrasonicDriver`；
3. 初始化 `UltrasonicApp`；
4. Arduino `loop()` 只休眠，业务由 FreeRTOS 任务处理。

驱动初始化内容：

- GPIO4～GPIO7 先置低，避免启动脉冲；
- LEDC Timer 0 使用 80 MHz APB 时钟；
- 默认载波 40 kHz，可在 38～42 kHz 间以 100 Hz 步进调整；
- 分辨率为 10-bit，即每周期 1024 counts；
- 最大有效占空比限制为 512 counts，即 50%；
- 上电默认占空比为 0，输出关闭。

应用层创建两个任务：

| 任务 | 优先级 | 职责 |
|---|---:|---|
| `controlTask` | 2 | 解析串口字符并把命令放入队列 |
| `playbackTask` | 8 | 独占调制器、GPTimer状态和LEDC驱动 |

命令队列长度为 8。播放任务固定到注册 GPTimer 中断的同一核心，以减少跨核通知抖动。

## 5. 控制命令流

```text
串口字符
→ controlTask解析
→ Command {type, value}
→ FreeRTOS命令队列
→ 通知playbackTask
→ 启停输出或改变配置
```

| 命令 | 行为 |
|---|---|
| `0`+回车 | 停止调制定时器并把四路 LEDC 占空比置 0 |
| `1`～`4`+回车 | 单独开启 GPIO4～GPIO7 中的一路 |
| `A` | 四路输出当前载波、50%占空比 |
| `T` | 启动 1 kHz 连续正弦包络 |
| `20`～`3000`+回车 | 启动指定频率的连续正弦包络 |
| `P` / `L` | Flash PCM 播放一次 / 循环播放 |
| `D` / `S` | 下次音频使用 DSB-AM / SRAM |
| `R` / `E` | 下次音频使用原始 PCM / 响度增强 PCM |
| `N` / `B` | 下次纯音或音频使用 STANDARD / BOOST 包络 |
| `-`、`[` / `+`、`]` | 载波降低 / 升高 100 Hz |
| `C` / `F` | 恢复 40 kHz / 打印实际载波 |
| `H` / `?` | 打印帮助 |

`D/S/R/E/N/B`只选择后续播放参数，不改变已经开始的纯音或音频。当前 120 阵元板上，单通道命令只有`1`会驱动阵列；`A/T/P/L`虽然在软件中更新四路，但整机只使用 GPIO4。

## 6. 三种发射路径

### 6.1 固定载波

`1～4`或`A`直接写 LEDC，不启动 8 kHz采样定时器：

```text
duty = 512
hpoint = (1024 - duty) / 2 = 256
```

结果是当前载波频率下、50%占空比、脉冲中心固定的连续方波。

### 6.2 正弦包络测试

纯音使用 8 kHz 更新率、32位相位累加器和256点正弦查找表：

```text
目标频率 → 相位累加器 → 正弦表索引 → 包络表 → duty
```

| 模式 | 包络 |
|---|---|
| STANDARD | `E = 0.55 + 0.40·sin(ωt)` |
| BOOST | `E = 0.50 + 0.48·sin(ωt)` |

支持 20～3000 Hz，不要求目标频率整除 8 kHz。

### 6.3 Flash PCM音频

```text
Flash中的uint8_t样本
→ RAW或LOUD处理
→ DSB-AM或SRAM查找表
→ ModulationFrame
→ 四路LEDC duty更新
```

LOUD 模式包含约 `2/128` 的噪声门和约 6 倍的小信号增益，并在接近满幅时软压缩。相关变换在初始化时预先生成256项查找表，播放期间不逐样本执行浮点压缩计算。

调制公式为：

```text
s = (sample - 128) / 128

DSB-AM: E = b + d·s
SRAM:   E = sqrt((b+d)·(b+d·s))
```

| 驱动模式 | `b` | `d` | DSB理论包络范围 |
|---|---:|---:|---:|
| STANDARD | 0.45 | 0.40 | 0.05～0.85 |
| BOOST | 0.50 | 0.48 | 0.02～0.98 |

这里的 SRAM 指 Square-Root Amplitude Modulation，不是 ESP32 片上存储器。

## 7. 包络如何变成40 kHz PWM

40 kHz 方波基波幅值近似与 `sin(πD)` 成正比，因此调制层使用反正弦映射：

```text
D = asin(E) / π
duty = round(D × 1024)
```

结果限制在 `1～512` counts。驱动层再计算：

```text
hpoint = (1024 - duty) / 2
```

这样改变占空比时，高电平脉冲仍围绕计数周期中心排列，减少由单边沿移动导致的附加相位变化。四个软件通道共用同一个 LEDC Timer，并使用相同的 `duty` 和 `hpoint`；当前没有通道相位表。

## 8. 8 kHz调度与积压处理

GPTimer 分辨率为 40 MHz。8 kHz采样对应：

```text
40,000,000 / 8,000 = 5,000个计数 = 125 µs
```

默认 40 kHz载波周期为25 µs，因此一个音频样本理论上覆盖5个载波周期。

GPTimer ISR不读取音频、不写LEDC，也不打印串口，只执行：

1. `pendingTimerTicks++`；
2. 通知 `playbackTask`。

播放任务醒来后读取积压节拍。若积压多于1个，就跳过已经过期的PCM样本或纯音相位，只渲染最新帧，从而保持音调和总时长，而不是把整段音频放慢。发生跳帧后，停止时会打印 `TIMING WARNING`。

当前调制不是载波同步 DMA：8 kHz更新由任务执行，LEDC四通道也依次触发更新。最终时序和毛刺仍需示波器或逻辑分析仪验证。

## 9. GPIO4到120阵元

```text
GPIO4
→ 10Ω串联、10kΩ下拉
→ U0前三路缓冲
→ U1/U2/U3各四路缓冲
→ 12路同相3.3 V逻辑
→ 每路47Ω串联、10kΩ下拉
→ 对应TC4428A的IN_A与IN_B
```

SN74HC125只负责逻辑扇出。换能器能量来自12 V电源，而不是GPIO或3.3 V逻辑电源。

每片TC4428A的两个输入接在同一逻辑节点，一路反相、一路同相，形成互补输出：

```text
TC4428 pin 7 OUT_A ──4.7Ω──┐
                           ├─ 10只TCT40-16T并联
TC4428 pin 5 OUT_B ─────────┘
```

12 V供电时，两端分别在约0～12 V间互补切换，换能器组得到接近24 Vpp的浮动差分方波。12组接收同一时间序列并同相发射，形成固定轴向超声波束；空气非线性再从超声包络中产生可听成分。

## 10. 电源、视觉与安全边界

数据流和能量流必须分开理解：

```text
GPIO4数据 → SN74HC125 → TC4428输入
3.3 V能量 → SN74HC125
12 V能量 → 12片TC4428 → 120只换能器
PUBLIC GND → ESP32、缓冲器和功率驱动的公共参考
```

摄像头和PC视觉只计算目标方向，云台执行机械转动。当前最小测试固件没有摄像头输入、舵机控制、逐通道相位或闭环跟踪逻辑。

串口`0`只停止40 kHz切换，不会切断12 V。TC4428在静态逻辑输入下仍可能保持一个输出高、另一个输出低。改线、插拔芯片或连接示波器前必须物理断开12 V。

## 11. 当前已知边界

- 固件名称和四通道实现仍对应旧12阵元原型，尚未收敛为专用的单GPIO整机固件；
- GPIO5～GPIO7在部分命令下仍会切换，不能把它们视为软件静音；
- 没有麦克风、I²S、USB Audio、网络或串口实时音频输入；
- 没有电子转向、聚焦、相位校准或逐组增益控制；
- 没有音频环形缓冲和DMA，Flash样本由任务逐字节读取；
- PWM占空比调制可能引入低频平均分量和非定向机械可听泄漏；
- 四通道更新不是严格的硬件同时锁存，实际同步程度需要测量；
- 手机麦克风和分贝App不能用于校准40 kHz声压或判断超声暴露安全。
