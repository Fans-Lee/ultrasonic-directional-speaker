## 1. 先明确当前版本

当前已经建立专用的 120 阵元固件：

- `src/full_size` 只配置一个 LEDC 输出通道和 `GPIO4`；
- GPIO4 由缓冲器扇出为 12 路同相信号，每路驱动 10 只换能器；
- 旧固件中的 GPIO5～GPIO7、四路更新循环和 `1～4` 单列命令已经删除；
- 当前没有电子相位转向或逐阵元控制，波束方向由二维机械云台改变；
- `src/esp32_s3_4x3_min_test_deprecated` 保留为历史 12 阵元台架，不再作为 120 阵元烧录入口。

因此，理解当前行为时按以下优先级判断：

1. 实际固件行为以 `src/full_size` 源码为准；
2. 当前整机接线以 [09-当前120阵元单GPIO接线.md](09-当前120阵元单GPIO接线.md) 为准；
3. [08-当前12阵元原型.md](08-当前12阵元原型.md) 和归档固件 README 只用于解释历史 4×3 台架；
4. 文档 01～07 已按当前 120 阵元机械转向基线重写；任何未来电子相控研究必须单独标记，不能覆盖当前接线。

## 2. 总数据流

```text
离线 PCM WAV
    │  wav_to_audio_header.py
    ▼
audio_data.h：8 kHz、8-bit、单声道 PCM，存入 Flash
    │
    │                    串口命令
    │                       │
    │                       ▼
    │              controlTask → 命令队列
    │                               │
    │          GPTimer ISR ─────────┤ 通知
    │          8 kHz节拍            ▼
    └──────────────────────→ playbackTask
                                    │
                                    ▼
                         ModulationEngine
                     固定载波 / 纯音 / PCM音频
                                    │
                                    ▼
                            duty + sampleRate
                                    │
                                    ▼
                 LEDC Timer 0 / Channel 0：默认40 kHz、10-bit
                                    │
                                  GPIO4
                                    │
                                    ▼
                       SN74HC125：1路扇出12路
                                    │
                                    ▼
                          12片 TC4428A
                         12 V互补差分输出
                                    │
                                    ▼
                      12组×10只并联换能器
                                    │
                                    ▼
                          120阵元同相超声波束
                                    │
                                    ▼
                         空气非线性产生可听声
```

串口现在复用实时音频、云台和控制消息。电脑端只有一个 `SerialDeviceLink` 拥有COM口；Flash播放仍可脱离电脑工作。

电脑参与时的完整闭环为：

```text
摄像头 → YOLO/ByteTrack → 目标角偏差 → PI与运动限制 → 云台角度 ─┐
                                                                ├→ 共享串口 → ESP32
麦克风/立体声混音/进程回环 → 滤波/压缩/限幅 → 8 kHz PCM_U8 → 音频帧 ─┘ ├→ 二维舵机
                                                                            └→ 调制/GPIO4 → 120阵元
```

## 3. 音频进入固件之前

转换工具位于 `utils/wav_to_audio_header.py`，处理过程为：

```text
未压缩PCM WAV
→ 多声道平均为单声道
→ 线性重采样到8 kHz
→ 去直流
→ 峰值归一化到约90%
→ 首尾各10 ms淡入淡出
→ 8位无符号PCM
→ 生成src/full_size/src/data/audio_data.h
```

生成的数组使用 `PROGMEM`，随固件烧入 Flash。当前头文件配置为：

| 项目 | 当前值 |
|---|---:|
| 采样率 | 8000 Hz |
| 样本格式 | 8-bit unsigned PCM |
| 样本数 | 36240 |
| 时长 | 4.53 s |
| `kAudioIsDemo` | `false` |

Flash播放时每个采样节拍通过 `pgm_read_byte()` 读取一个字节。实时模式则从2048样本的内部RAM环形缓冲读取；两种音源共用后续调制和LEDC链。更换内置音频仍需重新生成头文件并烧录。

## 4. 上电与软件任务

Arduino 入口 `src/full_size/full_size.ino` 依次执行：

1. 启动 460800 波特率串口；
2. 初始化 `UltrasonicDriver`；
3. 初始化 `UltrasonicApp`；
4. Arduino `loop()` 只休眠，业务由 FreeRTOS 任务处理。

驱动初始化内容：

- GPIO4 先置低，避免启动脉冲；
- LEDC Timer 0 使用 80 MHz APB 时钟；
- 默认载波 40 kHz，可在 38～42 kHz 间以 100 Hz 步进调整；
- 分辨率为 10-bit，即每周期 1024 counts；
- 最大有效占空比限制为 512 counts，即 50%；
- 上电默认占空比为 0，输出关闭。

应用层创建两个任务：

| 任务 | 优先级 | 职责 |
|---|---:|---|
| `controlTask` | 2 | 解析串口字符并把命令放入队列 |
| `playbackTask` | 8 | 独占调制器、GPTimer状态和LEDC驱动 |

命令队列长度为 8。播放任务固定到注册 GPTimer 中断的同一核心，以减少跨核通知抖动。

## 5. 控制命令流

```text
串口字符
→ controlTask解析
→ Command {type, value}
→ FreeRTOS命令队列
→ 通知playbackTask
→ 启停输出或改变配置
```

| 命令 | 行为 |
|---|---|
| `0`+回车 | 停止调制定时器并把 GPIO4 LEDC 占空比置 0 |
| `A` | 完整阵列输出当前载波、50%占空比 |
| `T` | 完整阵列启动 1 kHz 连续正弦包络 |
| `20`～`3000`+回车 | 启动指定频率的连续正弦包络 |
| `P` / `L` | Flash PCM 播放一次 / 循环播放 |
| `D` / `S` | 下次音频使用 DSB-AM / SRAM |
| `R` / `E` | 下次音频使用原始 PCM / 响度增强 PCM |
| `N` / `B` | 下次纯音或音频使用 STANDARD / BOOST 包络 |
| `-`、`[` / `+`、`]` | 载波降低 / 升高 100 Hz |
| `C` / `F` | 恢复 40 kHz / 打印实际载波 |
| `H` / `?` | 打印帮助 |

`D/S/R/E/N/B`只选择后续播放参数，不改变已经开始的纯音或音频。所有发射命令最终只更新 GPIO4，外部 SN74HC125 再把它复制到 12 路功率支路。

## 6. 三种发射路径

### 6.1 固定载波

`A`直接写单个 LEDC 通道，不启动 8 kHz采样定时器：

```text
duty = 512
hpoint = (1024 - duty) / 2 = 256
```

结果是当前载波频率下、50%占空比、脉冲中心固定的连续方波。

### 6.2 正弦包络测试

纯音使用 8 kHz 更新率、32位相位累加器和256点正弦查找表：

```text
目标频率 → 相位累加器 → 正弦表索引 → 包络表 → duty
```

| 模式 | 包络 |
|---|---|
| STANDARD | `E = 0.55 + 0.40·sin(ωt)` |
| BOOST | `E = 0.50 + 0.48·sin(ωt)` |

支持 20～3000 Hz，不要求目标频率整除 8 kHz。

### 6.3 Flash PCM音频

```text
Flash中的uint8_t样本
→ RAW或LOUD处理
→ DSB-AM或SRAM查找表
→ ModulationFrame
→ GPIO4 LEDC duty更新
```

LOUD 模式包含约 `2/128` 的噪声门和约 6 倍的小信号增益，并在接近满幅时软压缩。相关变换在初始化时预先生成256项查找表，播放期间不逐样本执行浮点压缩计算。

调制公式为：

```text
s = (sample - 128) / 128

DSB-AM: E = b + d·s
SRAM:   E = sqrt((b+d)·(b+d·s))
```

| 驱动模式 | `b` | `d` | DSB理论包络范围 |
|---|---:|---:|---:|
| STANDARD | 0.45 | 0.40 | 0.05～0.85 |
| BOOST | 0.50 | 0.48 | 0.02～0.98 |

这里的 SRAM 指 Square-Root Amplitude Modulation，不是 ESP32 片上存储器。

## 7. 包络如何变成40 kHz PWM

40 kHz 方波基波幅值近似与 `sin(πD)` 成正比，因此调制层使用反正弦映射：

```text
D = asin(E) / π
duty = round(D × 1024)
```

结果限制在 `1～512` counts。驱动层再计算：

```text
hpoint = (1024 - duty) / 2
```

这样改变占空比时，高电平脉冲仍围绕计数周期中心排列，减少由单边沿移动导致的附加相位变化。当前只有一个软件输出通道；12 路同步复制由外部缓冲器完成，不存在软件逐通道更新时间差，也没有通道相位表。

## 8. 8 kHz调度与积压处理

GPTimer 分辨率为 40 MHz。8 kHz采样对应：

```text
40,000,000 / 8,000 = 5,000个计数 = 125 µs
```

默认 40 kHz载波周期为25 µs，因此一个音频样本理论上覆盖5个载波周期。

GPTimer ISR不读取音频、不写LEDC，也不打印串口，只执行：

1. `pendingTimerTicks++`；
2. 通知 `playbackTask`。

播放任务醒来后读取积压节拍。若积压多于1个，就跳过已经过期的PCM样本或纯音相位，只渲染最新帧，从而保持音调和总时长，而不是把整段音频放慢。发生跳帧后，停止时会打印 `TIMING WARNING`。

当前调制不是载波同步 DMA：8 kHz更新由任务执行，LEDC更新时刻没有与40 kHz周期边界硬件锁存。最终时序和毛刺仍需示波器或逻辑分析仪验证。

## 9. GPIO4到120阵元

```text
GPIO4
→ 10Ω串联、10kΩ下拉
→ U0前三路缓冲
→ U1/U2/U3各四路缓冲
→ 12路同相3.3 V逻辑
→ 每路47Ω串联、10kΩ下拉
→ 对应TC4428A的IN_A与IN_B
```

SN74HC125只负责逻辑扇出。换能器能量来自12 V电源，而不是GPIO或3.3 V逻辑电源。

每片TC4428A的两个输入接在同一逻辑节点，一路反相、一路同相，形成互补输出：

```text
TC4428 pin 7 OUT_A ──4.7Ω──┐
                           ├─ 10只TCT40-16T并联
TC4428 pin 5 OUT_B ─────────┘
```

12 V供电时，两端分别在约0～12 V间互补切换，换能器组得到接近24 Vpp的浮动差分方波。12组接收同一时间序列并同相发射，形成固定轴向超声波束；空气非线性再从超声包络中产生可听成分。

## 10. 电源、视觉与安全边界

数据流和能量流必须分开理解：

```text
GPIO4数据 → SN74HC125 → TC4428输入
3.3 V能量 → SN74HC125
12 V能量 → 12片TC4428 → 120只换能器
PUBLIC GND → ESP32、缓冲器和功率驱动的公共参考
```

摄像头和PC视觉负责计算目标方向，ESP32固件接收云台角度并驱动二维舵机，同时输出超声调制。YOLO、目标锁定和闭环PI仍在电脑端；固件没有摄像头输入、逐通道相位或独立的视觉跟踪逻辑。

串口`0`只停止40 kHz切换，不会切断12 V。TC4428在静态逻辑输入下仍可能保持一个输出高、另一个输出低。改线、插拔芯片或连接示波器前必须物理断开12 V。

## 11. 当前已知边界

- 120 阵元固件已经收敛为 GPIO4 单输出，但仍未加入独立硬件 OE/12 V 断电控制；
- 已支持麦克风、Realtek 立体声混音与不受物理扬声器音量/静音影响的 Windows 进程回环；尚未实现ESP32本地I²S麦克风、USB Audio设备类或网络音频；
- 进程回环在数字静音持续 1 s 后停止实时流和 PWM，检测到内容后自动重启与预缓冲；
- 没有电子转向、聚焦、相位校准或逐组增益控制；
- 实时音频有内部RAM环形缓冲，但Flash和实时流仍由任务逐样本更新，没有载波同步DMA；
- PWM占空比调制可能引入低频平均分量和非定向机械可听泄漏；
- GPIO4到12路缓冲输出、12片TC4428传播延时和实际同相程度仍需要测量；
- 手机麦克风和分贝App不能用于校准40 kHz声压或判断超声暴露安全。
