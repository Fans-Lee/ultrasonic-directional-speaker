# 05 · 当前实施计划、分工与集成规则

> 版本：v2.0
> 日期：2026-09-13
> 基线：120 阵元单 GPIO、机械云台、电脑视觉和实时音频

本计划不再包含旧的 96 阵元、8/16 路电子相控路线。电子转向或聚焦若恢复，应单独立项，不得在当前整机调试中临时混入。

## 1. 项目管理原则

1. 以可复现验收门为进度，不以“代码写完”或日期代替通过。
2. 一次只改变一个关键变量：供电、负载数量、载波、调制、音源或控制参数。
3. 软件、逻辑、功率、声学和机械逐级集成，不第一次上电就接满 120 阵元。
4. 当前行为以源码和文档 09～13 为准，旧原型只作历史参考。
5. 每项性能结论必须指向原始数据、配置、固件提交和测量条件。
6. 功能失败时回退到最近一个通过验收的状态，不在现场继续叠加改动。

## 2. 工作包

| 工作包 | 内容 | 主要输出 | 验收依据 |
|---|---|---|---|
| WP1 桌面软件 | UI、视觉、控制、实时音频、配置 | `src/vision_gimbal`、测试 | 全量测试、仿真运行、状态日志 |
| WP2 ESP32 固件 | 协议、缓冲、调制、GPIO4、舵机 | `src/full_size` | 编译记录、GPIO/串口测试 |
| WP3 逻辑扇出 | U0～U3 和 12 路编号 | 接线、波形、映射表 | 12 路同相和幅值检查 |
| WP4 功率驱动 | P1～P12、去耦、阻尼、配电 | 驱动板和温升记录 | 单片到 12 片逐级测试 |
| WP5 阵面结构 | 120 阵元、极性、安装、云台 | 阵面、线束和结构图 | 连通、极性、重心和干涉检查 |
| WP6 声学测量 | 方向图、频响、失真和噪声 | 原始数据、图表、条件说明 | 可复现测量流程 |
| WP7 集成与答辩 | 完整启动、回退、安全和演示 | 演示包、检查表、备份 | 冷启动演练和故障回退 |

## 3. 三人参考分工

### A：软件与嵌入式

- 维护 `src/vision_gimbal`、`src/full_size`、协议和配置；
- 保证 `uv.lock`、测试和启动文档可复现；
- 输出 GPIO4、GPTimer、串口状态和错误计数的解释；
- 不在未经硬件确认时自行扩大电压、调制度或舵机范围。

### B：电路与电源

- 负责 SN74HC125、TC4428、12 V 配电、保险丝、去耦和阻尼；
- 逐级保存逻辑和差分波形、输入电流与温升；
- 确认示波器接地方式和改线断电流程；
- 不使用未经重新计算和实测的旧谐振电感方案。

### C：阵面、机械和测量

- 负责 120 个换能器编号、极性、焊接和结构固定；
- 负责云台重心、活动线束、限位和相机刚性安装；
- 执行方向扫描、频响、录音和环境记录；
- 维护实物照片、BOM 批次和答辩原始证据。

人员数量变化时可以合并角色，但验收责任不能消失。

## 4. 阶段门

### G0：仓库和接口可复现

- 根 README 的安装和启动命令可执行；
- `uv lock --check` 通过；
- 全量 Python 测试和语法检查通过；
- 当前正式入口只有 `vision_gimbal` 和 `src/full_size/full_size.ino`。

### G1：桌面端无硬件运行

- 摄像头打开并显示画面；
- YOLO/ByteTrack 输出人物轨迹；
- 显式选择、开始/停止跟踪和 WASD 行为正确；
- 未配置串口时不驱动硬件且 UI 不崩溃。

### G2：ESP32 低能量逻辑

- 固件使用锁定的 Arduino-ESP32 版本编译；
- 上电默认 GPIO4 关闭；
- `A/T/P/L/0/H` 台架命令行为正确；
- 二进制 HELLO、ACK、STATUS 和云台帧正确；
- 只上 3.3 V 时验证 GPIO4 与 12 路缓冲输出。

### G3：单功率通道

- 不接换能器时验证 TC4428 两输出互补；
- 单只换能器短时运行通过；
- 逐步增加到单组 10 只，记录波形、电流和温升；
- `RAW + STANDARD + DSB-AM` 作为首次音频模式。

### G4：12 路与 120 阵元

- P1～P12 逐片通过 G3；
- 三条 12 V 分支压降和回流合理；
- 120 个阵元极性、编号和分组与文档 09 一致；
- 全阵先短时运行，再逐步增加持续时间。

### G5：实时音频

- 内置 Flash PCM 可稳定播放；
- 同一 PCM 字节经串口发送时行为可对照；
- 麦克风、立体声混音和进程回环分别测试；
- CRC、gap、overrun、underrun、timer skip 和 host drop 有记录；
- 静音门能够停止无内容时的 PWM。

### G6：视觉云台闭环

- 相机与阵面固定关系稳定；
- 水平、垂直方向和软限位经过实物校准；
- 目标丢失后不自动切换到其他人物；
- 线束在全范围运动中不拉扯、不卷入结构；
- “停止追踪”与物理急停的边界清楚。

### G7：声学和长时间运行

- 在固定距离完成方向扫描；
- 保存可听频响和失真对照；
- 长时间运行记录温升和协议计数；
- 所有对外性能数字能追溯到原始文件。

## 5. 集成顺序

```text
软件单测
→ 摄像头/无串口仿真
→ ESP32 协议与 GPIO4
→ 12 路 3.3 V 逻辑
→ 单片 TC4428
→ 单组 10 只
→ 12 组 / 120 只
→ Flash 音频
→ 实时音频
→ 云台
→ 视觉闭环
→ 声学和长时验收
```

若某一级失败，先断开其后的模块，再在最近通过的边界上排查。

## 6. 变更控制

以下变更必须单独记录并重新跑受影响的验收门：

- GPIO、LEDC、GPTimer、串口波特率或协议布局；
- 每片 TC4428 的负载数量或供电电压；
- SN74HC125 型号、供电或扇出树；
- 音频采样率、包长、缓冲和超时；
- 调制公式、LOUD/BOOST 参数；
- 舵机补偿、方向和软限位；
- 相机内参、分辨率或安装位置；
- 模型文件、推理后端或依赖锁。

提交说明至少包含：改了什么、为什么改、影响哪些验收门、如何回退。

## 7. 数据和文件规则

每份测量记录至少包含：

- 日期、操作者和 Git 提交；
- 固件入口和 Arduino-ESP32 版本；
- `vision_gimbal.toml` 或关键配置快照；
- 电源、负载、音源、调制模式和测试时长；
- 仪器型号、带宽、探头连接和测点；
- 原始数据文件，而不只是截图或结论。

运行日志和录音可先放在忽略的 `output/` 或 `work/` 中；一旦用于报告，应筛选、去除机器绝对路径并移入受版本控制的证据目录。

## 8. 功能冻结和演示

演示前至少完成一次从断电状态开始的完整演练：

1. 检查接线、保险丝、云台活动范围和人员位置；
2. 烧录已验证固件并保存二进制/版本信息；
3. 使用锁定依赖启动桌面程序；
4. 先验证视觉和云台，再接通 12 V 功率；
5. 从低能量模式验证音频；
6. 演示结束先断 12 V，再关闭逻辑和软件。

演示包应包含内置 Flash 音频、离线视频或截图、配置备份、USB 线、备用保险丝、备用 TC4428A 和可直接回退的稳定固件。

## 9. 完成定义

“完成”同时要求：

- 源码、依赖锁和文档一致；
- 软件测试与固件编译可复现；
- 硬件按逐级流程通过；
- 性能结论有原始测量；
- 安全和故障回退经过演练；
- 未来功能没有被写成当前能力。
