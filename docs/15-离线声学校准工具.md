# 离线声学校准工具

日期：2026-09-21。工具入口是 `utils/audio_calibration/calibrate.py`。它只处理文件，不接入 `src/vision_gimbal` 的 Qt、视觉或实时音频流程。

## 1. 环境与入口

在仓库根目录同步现有锁定环境：

```powershell
uv sync --locked --python 3.11
```

所有命令使用同一入口：

```powershell
uv run python .\utils\audio_calibration\calibrate.py --help
```

工具仅依赖已在 `pyproject.toml` 锁定的 NumPy 和 Python 标准库；不需要新的包。测试代码在 `tests/test_audio_calibration.py`，可运行：

```powershell
uv run python -m pytest -q tests/test_audio_calibration.py
```

## 2. 生成训练和测试激励

以下命令生成多音、带限噪声、不同输入峰值和不同随机种子的 8 kHz PCM_U8 激励。每个 take 都含：

```text
input.wav       实际 PCM_U8 WAV
input_u8.bin    将要发送的原始字节
input.h         可交给 audio_stream_probe.py 的 C++ 头文件
metadata.json   峰值、RMS、种子、SHA256 和固定播放设置
```

```powershell
uv run python .\utils\audio_calibration\calibrate.py prepare `
  --output .\output\audio_calibration\session_001 `
  --kinds multitone noise `
  --peaks 0.10 0.20 0.40 0.60 `
  --seeds 12 `
  --duration-s 8 `
  --processing raw --drive standard --modulation dsb
```

`prepare` 选项：

| 选项 | 默认值 | 作用 |
|---|---:|---|
| `--output` | 必填 | 新实验目录 |
| `--kinds` | `multitone noise` | 可选 `multitone`、`noise`、`chirp` |
| `--peaks` | `0.10 0.20 0.40 0.60` | 量化前请求的输入峰值，必须不超过 0.98 |
| `--seeds` | 6 | 每种信号和峰值的独立随机种子数量 |
| `--duration-s` | 8 | 每个信号的秒数 |
| `--low-hz` / `--high-hz` | 250 / 3000 | 激励频带 |
| `--processing` | `raw` | 记录 RAW 或 LOUD；辨识建议 RAW |
| `--drive` | `standard` | `standard` 或 `boost`；两档必须分别建模 |
| `--modulation` | `dsb` | `dsb` 或 `sram`；两种模式必须分别建模 |

命令会创建 `manifest.json`，按完整信号种子分入 train、validation、test。它不会使用或覆盖根目录 `data/` 的 WAV。

## 3. 播放、录音和配对

固定阵列位置、麦克风位置、录音增益、载波、RAW/LOUD、STANDARD/BOOST 和 DSB/SRAM。关闭录音端 AGC、降噪和回声消除。每一个 take 将独立麦克风原始录音保存为对应目录的 `recorded.wav`，例如：

```text
output/audio_calibration/session_001/multitone_a0.20_s03/recorded.wav
```

录音可为 8/16/24/32 bit PCM WAV。推荐 48 kHz；程序会做带限 48 kHz→8 kHz 降采样。它不录制麦克风，也不声明手机麦克风或普通声卡对 40 kHz 场一定线性。

发送时复用现有诊断工具，每次只播放一个 take，并将其串口日志保存到 take 目录：

```powershell
uv run python .\utils\audio_stream_probe.py `
  --serial-port COM5 `
  --audio-header .\output\audio_calibration\session_001\multitone_a0.20_s03\input.h `
  --processing raw --drive standard --modulation dsb `
  --repeats 1 `
  --log-jsonl .\output\audio_calibration\session_001\multitone_a0.20_s03\stream.jsonl
```

替换 `COM5` 为实际端口。此工具必须没有发生 underrun、overrun、CRC、sequence gap、timer skip 或 host drop 才能接纳该 take；发生任一异常则重录。`calibrate.py` 当前从声学波形估计固定延迟，不能替代前后同步标记对长录音的时钟漂移校正。因此，首轮请保持每条录音约 8 秒，并在录音软件里裁掉播放前后的长静音；有同步标记或已测时钟比例时，应先在外部处理后再将配对段交给本工具。

## 4. 拟合

所有 `recorded.wav` 就位后执行：

```powershell
uv run python .\utils\audio_calibration\calibrate.py fit `
  --manifest .\output\audio_calibration\session_001\manifest.json `
  --model .\output\audio_calibration\session_001\model_p123.npz `
  --orders 1 2 3 --taps 128 --ridge 0.001 --oversample 6
```

模型为固定参数并联 Hammerstein：

\[
\hat y[n]=c+\sum_{p\in P}h_p*\phi_p(x)[n].
\]

`phi_p` 先把 8 kHz 输入固定重建到较高采样率，计算 p 次幂后低通并回到 8 kHz。这避免直接在 8 kHz 平方造成的二次谐波混叠。`--oversample 6` 对应 48 kHz 特征处理；设为 1 可用于很快的低保真调试。

| 选项 | 默认值 | 作用 |
|---|---:|---|
| `--manifest` | 必填 | `prepare` 输出且已配对录音的清单 |
| `--model` | 必填 | 输出 `.npz` 模型；同名 `.report.json` 保存报告 |
| `--orders` | `1 2 3` | 保留的一、二、三阶分支；先比较 `1`、`1 2`、`1 2 3` |
| `--taps` | 128 | 每分支固定 FIR 长度，8 kHz 下约 16 ms |
| `--ridge` | 0.001 | L2 正则化；仅用验证集选取 |
| `--oversample` | 6 | 特征重建倍数；训练与预失真必须一致 |
| `--batch-size` | 4096 | 正规方程的分块样本数，内存紧张时减小 |
| `--low-hz` / `--high-hz` | 250 / 3000 | 报告 NMSE 的评估带宽 |

运行后先看 `validation` 的平均 NMSE，以及 `.report.json` 中按 take 列出的 NMSE、对齐延迟和 RMS。不要按训练集最低误差选模型，也不要因模型复杂就默认更好。

## 5. 冻结模型后的评估

只有在验证集选定模型和参数后，才检查 test 内容：

```powershell
uv run python .\utils\audio_calibration\calibrate.py evaluate `
  --manifest .\output\audio_calibration\session_001\manifest.json `
  --model .\output\audio_calibration\session_001\model_p123.npz `
  --split test `
  --output .\output\audio_calibration\session_001\test_report.json
```

`evaluate` 的 `--split` 可关闭，从而输出全部集合；`--low-hz` 和 `--high-hz` 与拟合报告相同。报告的 NMSE 是固定对齐、固定频带内实测输出相对模型预测的误差；它不是 THD 或绝对声压指标。

## 6. 离线预失真

线性基线保留一阶支路，并使用其完整固定特征链的解析梯度做投影迭代。这样 `--oversample 6` 的特征重建也被包含在补偿中：

```powershell
uv run python .\utils\audio_calibration\calibrate.py predistort `
  --model .\output\audio_calibration\session_001\model_p123.npz `
  --target .\data\human_test\test1.wav `
  --output .\output\audio_calibration\predistorted_test1 `
  --method linear --regularization 0.001 --peak-limit 0.60
```

`--target` 可为任意 PCM WAV；它只作为目标，绝不自动加入训练集。输出目录包含可播放的 `input.wav`、`input_u8.bin`、`input.h` 和量化后模型预测的 `predistort_report.json`。

`--method nonlinear` 使用完整模型的解析梯度进行投影迭代，选项为 `--iterations`（默认 40）、`--step-size`（默认 0.5）、`--energy-weight`（默认 0.0001）和 `--peak-limit`（默认 0.60）。在线性模式下，`--regularization`（默认 0.001）是对应的一阶模型输入能量正则化。它是离线实验功能：真实重放后仍需录音，并以与原始输入、线性均衡相同的目标声级比较。模型预测改善不构成真实失真改善的证据。

`--peak-limit` 必须保持在训练数据覆盖的输入范围内。目标不可达时降低目标声级或补采数据，不通过增大峰值或开启 LOUD 来规避限制。

## 7. 根目录 data 的冒烟测试

`data/` 中的 WAV 没有配对输入、录音条件和音量配比，禁止作为训练清单。它们可以只用于读入、降采样和特征计算的冒烟测试：

```powershell
uv run python .\utils\audio_calibration\calibrate.py smoke `
  --wav .\data\human_test\test1.wav `
  --wav .\data\linear\linear_chirp_250Hz_to_3000Hz_10s.wav
```

`smoke` 不读取 manifest、不写模型、不拟合，也不把这些文件复制到输出目录。

## 8. 不变性边界

一个模型只对应一组固定条件。以下任一变化都需要新 session 和新模型：RAW/LOUD、STANDARD/BOOST、DSB/SRAM、载波频率、阵列或麦克风的位置/角度、录音增益、明显不同供电或温度状态。该工具不把这些状态混合到同一个模型中。
