# 03 · 当前软件架构、接口与运行边界

> 版本：v2.1
> 日期：2026-09-26
> 适用范围：`src/vision_gimbal`、`src/full_size` 和协议 V1

当前软件由 Windows 桌面端和 ESP32-S3 固件组成。视觉识别、用户交互和音频预处理在电脑上运行；载波、调制、缓冲、舵机 PWM 和故障静音在 ESP32 上运行。

## 1. 软件全景

```text
┌──────────────── Windows 桌面端 ────────────────┐
│ 摄像头 → YOLO/ByteTrack → Kalman → 目标锁定    │
│                         → PI → 运动限制          │
│ 麦克风/电脑声音 → DSP → PCM_U8                 │
│ UI 意图 ────────────────┐                       │
│                          └→ SerialDeviceLink     │
└──────────────────────────────┬───────────────────┘
                               │ COBS + CRC16
┌──────────────────────────────▼───────────────────┐
│ ESP32：协议服务器、音频环形缓冲、8 kHz GPTimer  │
│        调制查表、GPIO4 LEDC、GPIO5/6 舵机 PWM   │
└──────────────────────────────┬───────────────────┘
                               │
                   云台 + 120 阵元超声发射链
```

电脑端只有一个对象拥有 COM 口。音频服务和云台控制都向 `SerialDeviceLink` 发布消息，不能各自打开串口。

## 2. 桌面端目录和依赖方向

```text
src/vision_gimbal/
├─ domain/          不依赖 UI 或硬件的数据合同
├─ ports/           摄像头、跟踪器、音源和设备链接口
├─ vision/          YOLO、ByteTrack、去重和逐 ID Kalman
├─ control/         目标锁定、近距离瞄准、PI、手动控制和限位
├─ audio/           滤波、重采样、电平、压缩、量化、录音和频谱
├─ spatial/         可选深度和相对自由场模型
├─ protocol/        Python 协议帧、CRC 和消息结构
├─ application/     生命周期、会话和服务编排
├─ infrastructure/  OpenCV、PortAudio、WASAPI 和串口适配器
├─ ui/              PySide6 控件、绘制和工作线程
├─ bootstrap.py     唯一组合根
└─ __main__.py      正式桌面启动入口
```

依赖方向为 `UI/infrastructure → application → control/vision/audio → domain/ports`。领域对象不应导入 PySide6、OpenCV 串口实现或 ESP32 细节。

## 3. 视觉流水线

```text
OpenCVCamera
→ YOLOByteTrackPeopleTracker（只检测 person 类）
→ suppress_duplicate_people
→ PerTrackKalmanSmoother
→ VisionSnapshot
```

每个 `TrackedPerson` 包含 `track_id`、边界框、检测中心、控制瞄准点、置信度和是否为真实观测。短期丢帧可以由 Kalman 预测补充，但预测有最大帧数和目标释放超时。

当前系统只做人检测和轨迹 ID，不做人脸识别或身份识别。

## 4. 目标会话和云台控制

控制链刻意要求用户显式选择目标：

1. 用户点击人物框，形成选中目标；
2. 用户点击“开始追踪”，选中目标才成为活动目标；
3. 自动追踪期间点击其他人只更新待切换目标；
4. 再次点击“开始追踪”后才切换；
5. 活动目标超时后停止自动追踪，不自动跳到其他人。

自动控制路径：

```text
TargetObservation
→ CloseRangeAimPolicy
→ CameraProjection
→ pan/tilt AxisVelocityPid
→ MotionRequest
→ CommandArbiter
→ GimbalMotionLimiter
→ GimbalSetpoint
→ DeviceGimbalSink
→ SerialDeviceLink
```

手动 `W/A/S/D` 只在停止自动追踪时生效。自动和手动请求统一经过速度、加速度和角度限制。

UI 显示的是最后下发的指令角度，不是编码器反馈；当前云台没有位置回读。

## 5. 音频流水线

音源包括：

- 麦克风；
- PortAudio 立体声混音；
- Windows WASAPI 进程回环；
- 固件内置 Flash PCM。

电脑端实时音频路径：

```text
48 kHz float32 / 10 ms
→ 单声道
→ 250 Hz 高通
→ 3 kHz 抗混叠低通
→ 有状态重采样到 8 kHz
→ 电平控制、压缩和 -1.5 dBFS 限幅
→ PCM_U8
→ 160 样本 / 20 ms 数据包
```

实时音频、状态帧和云台命令共享同一协议会话。进程回环持续数字静音 1 秒后，音频服务停止 ESP32 流和 PWM；检测到新内容后重新建立流并预缓冲。

主音量由桌面端滑块经可靠 `SET_VOLUME` 命令发送到固件。固件在 RAW/LOUD 之后、调制之前平滑衰减音频，实时流与内置 Flash PCM 共用；0% 使音频 PWM 关闭。桌面端从 `HELLO_ACK` 能力位确认固件支持后，先同步音量再启动流。

完整协议字段见 [12-实时麦克风与音频流协议.md](12-实时麦克风与音频流协议.md)。

## 6. 可选深度与相对声场

`SpatialFieldService` 是默认关闭的显示支路：

- 使用单槽队列，只保留最新帧；
- 不参与目标选择、PI、串口或音频；
- 需要 `spatial` 可选依赖和 OpenVINO 模型；
- 输出是相对自由场可视化，不是经过校准的 dB SPL；
- 推理持续超时会停用该显示支路，而不影响主控制链。

## 7. ESP32 固件结构

```text
src/full_size/
├─ full_size.ino
└─ src/
   ├─ app/         命令、任务、状态机和 GPTimer
   ├─ audio/       Flash 与实时环形缓冲音源
   ├─ driver/      GPIO4 超声和 GPIO5/6 舵机
   ├─ modulation/  DSB-AM、SRAM、包络和查表
   ├─ protocol/    COBS、CRC16 和协议服务器
   └─ data/        当前内置 PCM
```

固件创建控制任务和高优先级播放任务。GPTimer ISR 只累计节拍并通知播放任务，不在中断中读取音频、打印串口或执行完整调制。

当前输出只有一个超声 LEDC 通道。12 路同步由外部 SN74HC125 复制，不存在软件相位数组或逐路更新循环。

## 8. 协议 V1

每个原始帧包含：

```text
magic/version/type/flags/payload_length
session_id/sequence/sample_index/payload/crc16
```

原始帧经过 COBS 编码，并以前后 `0x00` 定界。可靠控制命令要求 ACK；音频数据不 ACK、不重传，损坏或过期音频直接丢弃。

关键消息：`HELLO`、`STREAM_START`、`AUDIO_DATA`、`STREAM_STOP`、`SET_MUTE`、`SET_VOLUME`、`GIMBAL_SETPOINT`、`STATUS` 和 `COMMAND_ACK`。

固件仍保留字母命令和文本 `(pan,tilt)` 作为台架操作接口，但正式桌面端使用二进制协议。

## 9. 配置合同

唯一当前项目配置是 `configs/vision_gimbal.toml`。相对路径以配置文件所在目录解析。配置加载器拒绝未知字段，以避免拼写错误静默生效。

关键边界：

- Python 3.10～3.12；推荐 3.11；
- 串口默认 460800 baud；
- 实时音频固定 8 kHz、单声道、PCM_U8；
- 固件云台协议范围为两轴 -90°～90°；
- `cuda` 与 `xpu` 依赖互斥；
- `spatial_field.enabled` 默认 `false`。

## 10. 生命周期与错误隔离

桌面程序启动顺序：设备链 → 视觉 → 控制 → 音频。关闭顺序首先停止音频采集和传输，再关闭控制、视觉和共享串口。

以下支路不得阻塞核心闭环：

- 频谱分析队列满时丢弃旧可视化块；
- 声场分析队列满时替换旧帧；
- 串口重连在后台进行；
- 迟到的旧音源回调不得进入新的音频会话。

## 11. 正式入口和测试

桌面程序：

```powershell
$env:PYTHONPATH = ".\src"
uv run python -m vision_gimbal --camera-index 0 --serial-port COM5
```

测试：

```powershell
uv sync --locked --python 3.11
uv run python -m pytest -q
uv run python -m compileall -q src utils
```

pytest 只收集 `tests/`。`src/cv_test_deprecated` 和 `src/esp32_s3_4x3_min_test_deprecated` 是历史实现，不是正式模块或测试入口。
